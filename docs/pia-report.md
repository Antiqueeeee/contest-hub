## 二、处理的合法性与必要性分析

### 2.1 处理基础

- 注册与报名均要求用户**主动勾选同意《隐私政策》**（后端强制校验，未勾选拒绝提交），处理基础为个人同意
- 身份证号作为敏感个人信息，在隐私政策同意之外设有**独立的单独同意勾选框**，不与隐私政策同意捆绑；授予/撤回均写入 `consent_logs`（含政策版本、IP、时间）

### 2.2 身份证号的必要性论证

- **为什么需要**：赛事报名需核验参赛者真实身份（防冒名顶替、资格审核、获奖证书署名依据），身份证号是当前可用的唯一强身份标识
- **为什么注册时不收**：身份证号仅在实际报名时才有处理必要性。平台已于 2026-07-26 完成最小必要改造——注册只收邮箱+密码+姓名；身份证号在**首次报名时收集并绑定到账号**（`contestants.id_number`，可空），后续报名复用，报名记录（`registrations`）不再冗余存储
- **匿名报名**（未注册直接报名）的身份证号存于 `registrations.form_data`，赛事结束超过 `registration_retention_days`（默认 180 天，后台可配）后由每日清理任务自动清除

### 2.3 其他字段

- 邮箱：登录账号标识、通知渠道，必要
- 姓名：成绩公示、报名展示，必要
- 单位/自定义字段：由赛事方业务需要决定，属管理员可配置项（自定义字段收集敏感信息的管控已列入合规整改待办，见 `docs/compliance-gaps.md` 2.16）
- IP/UA（审计日志）：网络安全法要求留存网络日志 ≥6 个月，属法定义务

## 三、风险识别与已有保护措施

| 风险 | 已有保护措施（已实现，可在代码中验证） |
|------|----------------------------------------|
| 数据库泄露导致身份证号明文外泄 | 身份证号以 **Fernet（AES-128-CBC + HMAC-SHA256）加密存储**（`EncryptedString` 字段类型，`ENCRYPTION_KEY` 环境变量管理密钥）；密码使用 bcrypt 单向哈希 |
| 接口返回暴露完整 PII | API 返回自动脱敏：身份证号 `3201****1234`、手机号 `138****5678`、邮箱 `a***@example.com`（`app/utils/crypto.py`） |
| 未经同意收集敏感信息 | 注册/报名隐私政策明示同意（后端强制校验）+ 身份证号单独同意 + `consent_logs` 同意流水 |
| 未授权访问管理后台数据 | JWT 认证（`JWT_SECRET` 签名，默认 120 分钟过期）、管理员/选手权限隔离 |
| 暴力破解、接口滥用 | 登录失败锁定（同账号 5 次失败锁 15 分钟、同 IP 10 次失败拒 15 分钟，基于审计日志统计）；登录/注册/报名/导出接口已加滑动窗口限流 |
| 导出文件长期滞留服务器 | 导出 Excel 由后台每日清理任务按 `export_retention_days` 自动删除（默认 1 天，`system_settings` 后台可配） |
| 报名数据无限期保存 | 软删除报名 30 天后物理清除（`deleted_registration_purge_days`）；已结束赛事匿名报名的身份证号 180 天后自动清除（`registration_retention_days`） |
| 敏感操作无法追溯 | 全量审计日志（`audit_logs`：事件类型、操作人、目标、IP、UA、结果），保留 ≥6 个月 |
| 数据泄露后无应对 | 已建立《数据安全事件应急预案》（`docs/incident-response.md`）：分级、封堵、取证、24h 报告主管部门、通知个人 |

## 四、残余风险与接受理由

| 残余风险 | 说明 | 接受理由 / 缓解措施 |
|----------|------|---------------------|
| 身份证号未做真实性核验 | 平台仅做格式校验，不对接公安库核验号码真实性 | 核验服务需接入第三方且涉及数据出境/共享评估，超出当前业务范围；冒用风险由赛事方现场核验兜底。接受 |
| 导出 Excel 含明文身份证号 | 为满足赛事方线下统计需求，导出文件为明文（代码注释明确说明），由管理员下载后自行保管 | 服务器侧已有缓解：默认 1 天自动删除 + 导出接口限流 + 审计记录；管理员侧依赖制度约束（专人保管、用后删除、禁传个人网盘）。接受，并在管理员操作中提示 |
| 邮箱明文存储 | 选手邮箱当前明文存储（管理员手机号已加密） | 已列入合规整改 P1 待办（`docs/compliance-gaps.md` 2.8），整改前接受该风险 |
| 单进程内存限流 | 限流为单机内存滑动窗口，重启后计数清零 | 平台为单实例部署，无横向扩展，窗口精度满足当前规模。接受 |
| 审计日志可被数据库管理员直接修改 | 未做日志防篡改（如 WORM 存储） | 已列入整改待办（等保 P2）；当前通过限制数据库访问人员缓解。接受 |
| 备份文件中的 PII 存续 | 数据库备份（`scripts/backup.sh`，保留 30 天）含加密的身份证号与当时的账号数据；用户注销后，其已清除的 PII 在备份中最长继续存续 30 天 | 身份证号在备份中仍为 Fernet 密文；注销账号的明文 PII 已从主库不可恢复地清除，备份随 30 天轮转自动过期。该存续为备份恢复的合理代价，已在隐私政策保存期限说明范围内。接受 |

## 五、评估结论

平台处理敏感个人信息（身份证号）具有明确、合理的目的（赛事报名核验），已落实加密存储、接口脱敏、单独同意、访问控制、保存期限最小化、登录防护与应急预案等保护措施，处理活动对个人的安全风险经缓解后处于可接受水平。
