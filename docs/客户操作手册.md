# 客户操作手册（竞赛信息发布平台）

> 版本：v1.0（2026-07-26）
> 读者：赛事运营人员（不需要任何技术背景）

**这套系统是干什么的：** 用于发布竞赛信息、接收选手在线报名、发布成绩、导出报名数据。

**这份文档是干什么的：** 系统已经内置了法律要求的各项安全保护（选手的身份证号加密存储、有隐私政策、有防暴力破解锁定、过期数据自动清理等），但有些事情系统替不了你做——比如把隐私政策里的联系方式换成你自己的、安排数据泄露时的负责人。照着下面的清单做一遍，日常再注意几件事，合规义务就基本尽到了。

---

## 一、上线前必须做的（按顺序逐项完成）

### 1. 登录后台，改掉初始密码

- 后台地址：`http://你的服务器地址/admin/login`，用户名 `admin`
- 初始密码是系统首次启动时随机生成的，**只显示在服务器的启动日志里**。让部署人员在服务器上执行：

  ```bash
  docker compose logs backend | grep 管理员
  ```

  输出里就能看到初始密码。
- 第一次登录后**立即改密码**：点后台**右上角的钥匙图标**（鼠标放上去会显示「修改密码」），输入原密码和新密码。
- 新密码要求：8–64 位，字母、数字、符号至少包含两种。请抄在纸上锁进抽屉，或用密码管理工具保存，**不要贴在显示器上，也不要发到微信群里**。

### 2. 填写隐私政策里的占位信息

隐私政策页面对所有选手公开（前台首页底部「隐私政策」链接），里面留了几处占位文字，必须换成你单位的真实信息：

- 登录后台 → 左侧菜单「站点内容」→ 选择「隐私政策」
- 把【请平台运营方填写联系邮箱】【请平台运营方填写联系电话】等占位内容替换为实际值，保存
- 保存后自己打开前台首页底部的「隐私政策」确认一下显示正常

### 3. 填写应急预案里的负责人

项目文件夹里有一份 `docs/incident-response.md`（数据安全事件应急预案），规定了一旦发生数据泄露谁来指挥、怎么处置、怎么通知选手和主管部门。

- 打开这个文件，把所有【待填写：xxx】的地方填上：**应急负责人、技术联系人、个人信息保护负责人**（姓名+手机+邮箱），以及单位全称
- 应急负责人必须是出事时能第一时间拍板的人（比如部门主管），技术联系人必须能操作服务器
- **打印一份放在办公室**，出事了不一定来得及开电脑翻文件

### 4. PIA 报告签字确认

`docs/pia-report.md` 是《个人信息保护影响评估报告》，是法律（个人信息保护法第 55 条）要求在处理身份证号这类敏感信息之前必须做的评估，**报告要求至少保存三年**。

- 打开文件，核对内容与实际运营情况一致
- 在末尾「评估人签字」处写上评估人姓名，填上日期；「评估人」「审核人」两处占位符也一并填好

### 5. 配置 HTTPS（需要技术人员协助）

**什么是 HTTPS：** 就是网址以 `https://` 开头、浏览器地址栏带小锁标志。它让选手的密码、身份证号在你服务器和选手浏览器之间**加密传输**，防止被中途偷看。法规（等保 2.0）对此有明确要求。

- 让技术人员或服务商按 `README.md` 的「配置 HTTPS」一节操作（申请证书、配置外层 nginx）
- 配好后还需要两步收尾（同样由技术人员做）：
  1. 把项目根目录 `.env` 文件里的 `FORCE_HTTPS=true` 这一行取消注释（删掉开头的 `#`），然后重启服务（`docker compose up -d`）。开启后，凡是不走 HTTPS 的敏感请求（登录、注册、导出）会被系统直接拒绝
  2. 按 `.env.example` 里 HTTPS 段的说明，取消 `frontend/nginx.conf` 顶部 map 中那一行透传配置的注释
- 验收方法：用 `http://` 开头的地址访问登录页，应被自动跳转或拒绝；地址栏应显示小锁

### 6. 设置自动备份

**什么是备份：** 把数据库定期完整复制一份存起来。服务器硬盘损坏、误删数据、被攻击加密时，靠备份恢复。法规（等保 2.0）要求必须做。

系统自带备份脚本 `scripts/backup.sh`，让技术人员在服务器上设置每天自动执行：

```bash
# 先手动试跑一次，确认 backups/ 目录里生成了 .sql.gz 文件
cd /opt/contest-hub && bash scripts/backup.sh

# 再设置为每天凌晨 3 点自动执行（编辑定时任务：crontab -e，加入下面一行）
0 3 * * * cd /opt/contest-hub && bash scripts/backup.sh >> backups/backup.log 2>&1
```

脚本会自动：压缩备份、按日期时间命名、只保留最近 30 天、失败时报错。

**最重要的一条：备份文件不能只放在这台服务器上。** 服务器一旦整体损坏或被勒索，备份会连同数据一起丢失。请安排人**每周至少一次**把 `backups/` 目录里最新的备份文件拷贝到另一台电脑或专用移动硬盘/U 盘上，异地保管。备份文件里有选手的敏感数据，拷备份的 U 盘同样要锁好，不能随手乱放。

## 二、日常使用中要注意的

### 1. 导出的选手 Excel 要当"机密文件"对待

后台「数据导出」生成的 Excel 里包含选手的**完整身份证号**（这是赛事统计必需的）。请遵守：

- 谁导出、谁负责保管；文件用后**立即删除**，不要长期存在个人电脑里
- **不要**发到微信群、QQ 群，**不要**上传到个人网盘（百度网盘等）、邮箱附件也尽量避免
- 需要给赛事主办方时，通过加密压缩包（密码另用电话告知）或当面拷贝交付
- 服务器上的导出文件系统**每天会自动删除**（默认保留 1 天，后台「系统设置」里可调整，建议不要调长）

### 2. 不要用自定义报名字段收集敏感信息

创建赛事时可以给报名表单加自定义字段，但系统会**自动拦截**字段名里含有「身份证、护照、健康、病史、民族、宗教、政治面貌、指纹、人脸、银行卡」等敏感字眼的字段——因为法律（个人信息保护法）把这类信息列为敏感个人信息，收集需要满足严格条件，而身份证号平台已有内置字段统一收集（加密存储+单独同意）。

请配合：**不要试图绕开拦截**（比如改用拼音、缩写、错别字命名）。如果你确实认为某个敏感字段是赛事必需的，先联系开发方评估合规性，不要自己变通。

### 3. 选手要求注销账号、查看或导出自己的数据时

**不需要你人工处理。** 选手登录前台后，在「个人中心」里自己就能完成：

- 查看自己的全部信息（身份证号脱敏显示）
- 导出我的数据（下载包含账号资料、报名记录、成绩、授权记录的 JSON 文件）
- 管理授权（查看/撤回同意记录）
- 注销账号（输入密码确认后，姓名、身份证号、邮箱被清除或匿名化，报名和成绩记录匿名保留，不影响赛事统计）

如果有选手打电话来要求做这些操作，指引他登录个人中心即可。

### 4. 如果赛事面向 14 岁以下儿童（未成年人保护模块）

法律对 14 岁以下儿童的个人信息有**额外要求**（必须取得监护人同意等）。系统已提供**可选启用的未成年人保护模块**，操作分两步：

1. **系统级开关**（部署时决定，由运营方确认）：后台「系统设置」→「未成年人保护（可选启用）」打开开关。打开后，创建赛事时会出现「面向未成年人」选项。
2. **赛事级开关**（每场赛事分别决定）：创建/编辑赛事时，在「基本信息」里把「面向未成年人」选为「是」。只有被标记的赛事才走未成年人流程：

   - 报名时收集出生日期（加密保存，用于按**赛事开始日**判定年龄）
   - **14 周岁以下**：要求填写监护人姓名、联系方式并勾选监护人同意（系统留痕）
   - **14-18 周岁**：要求本人勾选「已满 14 周岁」声明
   - 未标记的赛事、未打开系统开关的客户，报名流程与以前完全一样，不受任何影响

⚠️ 责任提醒：**开关是为客户服务的工具，不是免责凭证**。如果你的赛事确实面向 14 岁以下儿童，必须打开系统开关并在赛事上标记「面向未成年人」；只打开开关却不在赛事上标记，系统不会收集监护人同意，此时的法律责任由赛事主办方承担。如赛事出现 14 岁以下选手的监护人要求查询、更正、删除子女信息，可引导其通过隐私政策页的联系方式联系平台处理。

## 三、每年要做的（建议固定时间，比如每年 1 月）

| # | 事项 | 具体做法 | 留痕 |
|---|------|----------|------|
| 1 | 合规自查 | 对照 `docs/compliance-gaps.md` 开头「已满足项」表格逐项过一遍：隐私政策还在吗、勾选框还强制吗、锁定限流还生效吗 | 自查记录签字存档 |
| 2 | 数据安全培训 | 组织所有接触后台的运营人员通读本手册 + `docs/incident-response.md` 应急预案 | 保留签到表/照片 |
| 3 | 检查备份在跑 | 打开服务器 `backups/` 目录，确认最近每天都有新的 `.sql.gz` 文件；抽查一个文件大小是否正常（不能是 0） | 记录检查日期 |
| 4 | 复核应急联系人 | 确认应急预案里填的负责人、电话仍然有效（人员离职要及时更新并重新打印） | 更新文档 |

## 四、出事了怎么办（数据泄露或怀疑泄露）

典型情形：收到选手举报信息被泄露、发现服务器异常、收到外部通报、管理员电脑/U 盘丢失且里面有导出文件。

1. **第一步：立即拨打应急预案（`docs/incident-response.md`）里填的应急负责人电话**，不要自己先处理
2. 之后的一切处置（关停服务、取证、通知选手、报告主管部门）都按预案里的流程执行——预案里已经写好了每一步的具体操作和通知模板
3. **不要自行删除任何数据或日志**，现场要保留给技术人员取证
4. 记住两个时限：**24 小时内**必须报告主管部门；确认涉及个人信息泄露后，尽快通知受影响的选手（模板在预案里）

## 五、系统已经自动做到的（列举备查，不用你操心）

- **身份证号加密存储**：数据库里存的是密文，即使数据库文件被盗也读不出号码
- **界面脱敏显示**：后台和接口里身份证号显示为 `3201****1234` 这种形式，完整号码只在导出的 Excel 里出现
- **密码加密存储**：所有密码以不可逆方式哈希存储，连管理员也看不到明文
- **隐私政策与同意**：注册、报名必须主动勾选同意《隐私政策》（不勾选提交不了）；收集身份证号时还要单独勾选一次同意，每次同意都有记录可查
- **防暴力破解**：同一账号连续登录失败 5 次锁定 15 分钟；同一 IP 失败 10 次拒绝 15 分钟；登录、注册、报名、导出接口都有访问频率限制
- **操作留痕**：登录、导出、增删改等关键操作全部记录日志（谁、什么时间、做了什么、来自哪个 IP），日志至少保留 6 个月；日志在数据库层面被设为"只能新增、不能删改"（防篡改），到期后 IP 地址自动匿名化
- **安全告警**：如果检测到有人在短时间内大量翻看报名数据，系统会记录一条安全告警日志。告警只是记下来，**不会主动通知任何人**——请运维人员定期（比如每周）查看日志里有没有 `security_alert_bulk_view` 类型的记录，有的话按应急预案排查
- **数据定期自动清理**：被删除的报名记录 30 天后彻底物理删除；赛事结束 180 天后，匿名报名里的身份证号自动清除；导出的 Excel 文件默认 1 天后自动从服务器删除（以上天数可在后台「系统设置」调整）
- **登录凭证自动过期**：登录状态默认 120 分钟后失效，需重新登录
- **每日自动备份**：按本手册第一节第 6 条设置后，数据库每天自动备份并保留 30 天
