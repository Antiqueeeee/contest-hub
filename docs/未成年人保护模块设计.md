## 二、设计原则

1. **条件性必填**：儿童保护相关字段（出生日期、监护人信息）一律可空；仅当系统级开关开启 **且** 赛事声明面向未成年人时，报名接口才强制校验。
2. **默认关闭**：系统级默认 `off`、赛事级默认 `normal`，现有流程、导出、测试零影响。
3. **复用现有机制**：加密存储（Fernet）、懒收集绑定账号、`consent_logs` 同意流水、保留期清理、注销 PII 脱敏——全部照抄身份证号的既有模式（`contestants.id_number`，见 `backend/app/models/contestant.py`）。

## 三、三级开关

### 3.1 系统级开关（客户部署时决定）

- 配置：`system_settings.minor_protection_mode = off | on`，默认 `off`
- `off`：注册/报名/导出/隐私政策**完全照旧**，前端不出现任何年龄相关 UI，后端接口不校验
- `on`：后台出现赛事级开关，报名表单出现出生日期，隐私政策展示「儿童个人信息保护」章节

### 3.2 赛事级开关（管理员创建赛事时决定）

- 字段：`contests.minor_policy = normal | minors_welcome`，默认 `normal`；系统开关 `off` 时该选项隐藏
- `normal`：报名流程与今天完全一致——客户不想用的赛事不受任何影响
- `minors_welcome`：报名时触发年龄分支

### 3.3 报名流程内按年龄分支

```
收集出生日期 birth_date（加密存储；账号选手懒收集绑定复用，匿名选手存 form_data）
        │
        ▼ 按赛事开始日 contest.start_date 计算年龄
        │  （不是报名日！资格判定以赛事日为准；存生日不存年龄）
   ┌────┼─────────┬──────────┐
   ▼    ▼         ▼          ▼
 ≥18   14-18      <14      （系统 off 或赛事 normal）
 正常  勾选声明    监护人流程   无任何变化
       已满14岁    ↓
   consent_logs  监护人姓名+联系方式（加密）
   记 minor_      + 监护人单独同意勾选
   statement     consent_logs 记 guardian_consent
```

## 四、数据模型变更（全部可空、向后兼容）

| 表 | 字段 | 类型 | 说明 |
|----|------|------|------|
| `contestants` | `birth_date` | `EncryptedString(512), nullable` | 出生日期，懒收集（首次报名面向未成年人的赛事时收集）。注：EncryptedString 长度是 Fernet 密文列长度，token 远长于明文，统一 512 |
| `contestants` | `guardian_name` | `EncryptedString(512), nullable` | 监护人姓名（<14 岁时收集） |
| `contestants` | `guardian_contact` | `EncryptedString(512), nullable` | 监护人联系方式 |
| `contests` | `minor_policy` | 枚举，默认 `normal` | 赛事级开关 |
| `system_settings` | `minor_protection_mode` | 键值，默认 `off` | 系统级开关，无需改表（`backend/app/models/system_setting.py`） |
| `consent_logs` | `consent_type` 新增枚举值 | `guardian_consent` / `minor_statement` | 无需改表（`backend/app/services/consent_service.py` 的 `CONSENT_TYPES` 扩展） |

## 五、同意、撤回与清理

- **撤回**：撤回 `guardian_consent` → 删除监护人信息与出生日期（不可恢复），照抄 `id_number` 撤回逻辑（`consent_service.withdraw_consent`）
- **注销**：出生日期、监护人信息纳入现有 PII 脱敏流程
- **匿名报名**：生日/监护人信息存 `registrations.form_data`，随 `registration_retention_days`（默认 180 天）清理任务清除
- **个人中心**：「授权管理」自动列出新同意类型（`get_consent_states` 按枚举遍历，无需改前端逻辑之外的部分）

## 六、合规依据与联动

| 依据 | 要求 | 本模块对应 |
|------|------|-----------|
| 《儿童个人信息网络保护规定》第 9/10 条 | 收集儿童个人信息前取得监护人同意；同时收集监护人联系方式 | 监护人流程 + `guardian_consent` 流水 |
| 同上 | 隐私政策需以儿童能理解的语言说明 | 儿童保护章节（`site_content` 可编辑，`mode=on` 时展示） |
| 《未成年人保护法》网络保护专章 | 14-18 岁建议家长通知 | MVP 以「已满 14 周岁」本人声明替代（见第九节） |
| 《个人信息保护法》 | 单独同意、加密、保存期限最小化 | 复用现有 `consent_logs` / Fernet / 清理任务 |

管理端访问控制：管理员暂无角色体系（`backend/app/models/user.py` 仅 active/disabled），MVP 为审计记录（查看儿童敏感字段复用 `security_alert_bulk_view` 批量告警模式）；「白名单管理员」角色列为二期。

## 七、边界情况

- **注册时未收生日**（曾报名普通赛事），后报 `minors_welcome` 赛事 → 该次报名时补收（懒收集，与身份证号一致）
- **同一账号不同赛事年龄不同** → 每次按各赛事开始日重算
- **匿名报名未成年人** → 流程一致，数据入 `form_data`
- **客户开了系统开关但赛事全 `normal`** → 实际流程零变化，年龄字段只出现在 `minors_welcome` 赛事

## 八、明确不做（二期 / 不纳入 MVP）

- 监护人身份真实性核验（与身份证号真实性核验同级，接受残留风险，PIA 备案）
- 管理端「白名单管理员」角色
- 14-18 岁家长主动通知（短信/邮件）——需额外收集家长联系方式，扩大收集范围，与最小化原则冲突；MVP 以本人声明替代
- 儿童个人信息加密强度升级（现有 Fernet 已满足）
