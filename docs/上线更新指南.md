# 上线更新指南

> 适用：docker compose 部署（项目根目录有 `docker-compose.yml`）
> 要点：**线上服务器资源差，一律先停旧服务再构建启动**，不要边跑边构建。

---

## 一、标准更新流程（每次上线照此执行）

```bash
# 1. 进入线上项目目录
cd ~/CodeSpace/contest-hub

# 2. 更新前备份数据库（必做！更新出错时可以恢复）
bash scripts/backup.sh
#    确认 backups/ 下生成了新的 contest_hub_日期.sql.gz，且文件大小不是 0

# 3. 拉取最新代码
git pull

# 4. 先停掉旧服务（释放内存，资源差时不能边跑边构建）
docker compose stop

# 5. 重新构建并启动
docker compose up -d --build

# 6. 验证
docker compose ps                 # db / backend / frontend 三个都是 Up
docker compose logs backend | grep "Running upgrade"   # 有数据库迁移时能看到执行记录
```

## 二、如果更新带了数据库迁移

后端容器启动时会自动执行 `alembic upgrade head`（见 `backend/docker-entrypoint.sh`），**不需要手动跑迁移**。日志里出现 `Running upgrade ...` 即说明迁移已执行。

## 三、忘记管理员密码

```bash
docker compose exec backend python seed.py --reset-admin
docker compose logs backend | grep 管理员   # 新密码打印在这里
```

登录后台（`http://服务器IP/admin/login`，用户名 `admin`）后立即改密码。

## 四、常见注意点

- **.env 不要覆盖**：`.env` 里有 `DB_PASSWORD` / `JWT_SECRET` / `ENCRYPTION_KEY`，后面两个一换，已加密的身份证号/邮箱全部读不出来。`git pull` 不会动它，但如果是解压交付包覆盖部署，必须把旧 `.env` 拷回来。
- **外层 HTTPS 网关**：如果当年配了 443 反向代理（`.env.example` 里的示例），它不在项目代码里，重建容器不会更新它。慢上传超时问题需在该网关的 `proxy_pass http://127.0.0.1:80` 处加 `proxy_read_timeout 300s; proxy_send_timeout 300s;` 再 `nginx -s reload`。
- **HTTPS 强制**：`FORCE_HTTPS=true` 需要外层代理总是覆写 `X-Forwarded-Proto`，否则会被绕开或误伤（见 `.env.example` 注释）。
- **初始密码只在首次启动日志里**：日志滚动后就找不回了，用第三节的方法重置。

## 五、回滚

如果更新后出问题：

```bash
docker compose stop
git log --oneline -5                      # 找到上一个正常提交
git checkout <上一个提交> -- .            # 或 git reset --hard <提交>（会丢本地改动）
docker compose up -d --build
```

- 回滚到旧代码后，**数据库不会自动降级**（迁移只向前）。若本次迁移改了表结构且业务依赖新结构，回滚后需人工处理（先联系开发方）。
- 数据恢复：用第二节备份的 `.sql.gz` 恢复（恢复操作也先联系开发方确认）。
