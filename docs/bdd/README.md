# BDD 特性文档

本目录以 Gherkin（Given/When/Then）描述系统的关键行为，是**验收标准的唯一权威来源**：

- 写给人看：客户、测试、开发对"系统应该是什么表现"的统一答案
- 写给测试看：`e2e/` 下的 Playwright 用例与这里的 Scenario 一一对应（用例标题标注 Scenario 编号）
- 维护规则：改行为先改这里的 Scenario，再改代码和测试

约定：

- 「选手」= 前台注册用户；「管理员」= 后台用户
- 「系统字段」= 报名内置的姓名/邮箱/身份证号；「自定义字段」= 管理员为赛事添加的额外收集项
- 测试环境的初始数据（管理员账号、赛事）由测试固件准备，不属于业务行为

## Scenario 与测试的对应关系

- **浏览器端（Playwright，`frontend/e2e/`）**：R1-R6、B1-B7、C1-C7、S1、A1、A5、P1、P6，
  共 20 条用例。运行方式：
  ```bash
  bash scripts/e2e-env.sh start          # 起一次性测试环境（PG 容器 + 后端 :8000 + 前端 :4173）
  cd frontend && npx playwright test     # 跑浏览器测试
  bash scripts/e2e-env.sh stop           # 用完关掉
  ```
- **服务层（pytest，`backend/tests/`）**：R7、A2-A4、A6-A8、P2-P5、P7 等不依赖浏览器的行为，
  由 26 项后端测试覆盖（见 `backend/tests/conftest.py` 头部运行说明）。
- 两侧都未覆盖的 Scenario 属于手工验收项（如运维类操作）。
